## B. Развилка дизайна (D-198 §2.7 — синтез перед выбором)

Кандидаты:

- **(A) Мемо ключ-сравнением (буквальный «двойник ScanGateMemo»)**:
  ключ = значения (position, caught) спека — сборка ключа стоит СТОЛЬКО
  ЖЕ, сколько сам фильтр. Ничья по построению — отклонён без замера.
- **(C) Хвосты DecayIndex (устаревание + валидация на виду)**: чтение
  здесь — перечисление ВСЕГО множества (не pop-min): валидация
  на виду переплатила бы пер-спековым фильтром на каждом чтении —
  ровно та цена, которую индекс существует срезать. Отклонён.
- **(B) Бакеты ПО ЛОКАЦИЯМ с ТОЧНЫМ поддержанием**: скоуп = членство в
  бакете; горячий путь (одиночная локация) — ноль аллокаций, сам
  список бакета. Недостаток — порядок и точность при переездах —
  нейтрализуется фолдом на пути коммита (перепроизводство из живого
  состояния) + insort по позиции спека.
- **Синтез (B)** удовлетворяет объединению преимуществ (точность без
  устаревания + канон-порядок + ноль аллокаций на горячем пути) и
  устраняет материальный недостаток (C). **Эмерджентное свойство,
  названное и проверенное: ЗАКОН ТОЧНОСТИ** — присутствие ИНВАРИАНТНО
  (гейт двери коммита поднимает на сущности вне сеяной проекции —
  _commit проверяет `props is None` ДО записи), значит вердикт
  двигают ТОЛЬКО position и crime_status, оба ездят событиями, и фолд
  перепроизводит членство из живого состояния — порядко-иммунно внутри
  события. Это не украшение: без инварианта присутствия фолд был бы
  неполон. Свойство переживает родителя по всем материальным осям.

## C. Изменение (4 файла кода/инструмент + 1 новый тест)

1. **`core/urgencies.py` — `RollIndex`**: бакеты
   `dict[position, list[(idx, spec)]]` (insort по idx — порядок
   пакета), `_spec_idxs` (npc → позиции спеков), `_where` (npc → ключ
   бакета — членство), `_bound` + рождение `from_projection(specs,
   projection)` (KI#16: целая initial-проекция; пойманные пропускаются)
   и штамп идентичности одной операцией (резюм перевыпускает).
2. **Фолд на пути коммита** (`_commit`, строка после фолда DecayIndex):
   `apply_change(entity, prop)` — только position/crime_status;
   снять-если-размещён (где держит `_where`; `list.remove` мимо —
   ГРОМКО), положить-если-не-пойман (живое чтение позиции). Каждый
   вызов — полное перепроизводство членства сущности: последний вызов
   события оставляет ответ живого состояния при ЛЮБОМ порядке
   изменений.
3. **Чтение `rolling(locations)`**: одиночная локация — сам список
   бакета (ноль аллокаций; read-only by contract — сканы не коммитят
   внутри); None — сортированное объединение всех бакетов; мульти
   (тёплое кольцо) — сортированное объединение названных (бакеты
   дизъюнктны — один спек ровно в одном бакете).
4. **Оба потребителя** (`urgency_scan`, `urgency_intents`):
   keyword-only `roll_index=None`; ветка индекса (гейт `serves`) даёт
   записи в порядке пакета — порядок вставки dict'ов скана и
   последовательность дроу обхода идентичны по построению; дефолт —
   фильтр (все прежние вызывающие не тронуты). Loop: рождение при
   construction, re-birth при resume, все три места вызова (скип-проба,
   бит, макро-тёплое-кольцо).
5. **`scripts/labrunner.py`**: комментарии членов beat_rolls/skip_probes
   (urgency_rolls — честное отсутствие в профиле теперь).

Фракционное семейство НАМЕРЕННО не индексировано: faction_scan
0.018 проф. с на стене — sub-noise; плотный фракционный пак открыл бы
свой ряд.

## D. Законы-оракулы (tests/test_rollidx.py — 9, все зелёные)

1. **Рождение == фильтр на всех шести коммитнутых паках** — по каждой
   форме скоупа (None / одиночные / мульти / мульти в другом порядке —
   порядко-нечувствительность) + многоспековый NPC (обе записи).
2. **Зубы рождения**: сеяные позиции читаются, пойманный
   двухспековый NPC не размещается (KI#16).
3. **ФОЛД-ДВОЙНИК после КАЖДОГО из 12 краёв** (скрипт через
   apply_event + фолд в порядке _commit): хоп бакета, возврат, no-op
   на месте, вето caught (обе записи уходят) + освобождение (обе
   возвращаются), suspected (членство не меняется), position+caught в
   одном событии ОБЕИХ порядков, два position в одном событии,
   двойной флип caught→free→caught, позиция очищена в None
   (None-бакет: катится в one-scene скоупе, фильтруется в каждом
   локированном).
4. **No-op фолд**: не-вердиктные пропы и чужие сущности не трогают
   бакеты.
5. **Скан-двойник на уровне функции**: ответы И порядок вставки
   dict'ов (коллективный обход читает порядок вставки).
6. **Обход-двойник + закон дроу**: одинаковые seed-банки — интенты
   равны И счётчики каждого стрима равны (последовательность дроу —
   канон-порядок).
7. **Гейт идентичности**: чужая проекция / свежий парс спеков / None
   не обслуживаются; обход на чужой проекции отвечает чужому виду
   (предикат).
8. **Реальный лог (провинция, p=100 ходок)**: двойник mid-run и на
   дренировании + живые бакеты == свежему рождению (фолд == скан).
9. **Резюм-закон**: перевыпущенный индекс связан с восстановленными
   объектами, двойник через дальнейшую игру.
