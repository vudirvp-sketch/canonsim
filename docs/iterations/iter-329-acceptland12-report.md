## D. KI#113 — анализ (единственная запись, полное)

Наблюдение: первый полный прогон сессии
(`pytest -q`, PYTHONHASHSEED=0, сразу после установки dev-зависимостей)
упал на `test_the_wall_split_accounting_law` с AssertionError;
повторный полный прогон и все последующие — зелёные. Вероятная
связь: фоновая нагрузка установки (pip/индексация) во время первого
прогона. Timing-чувствительные кандидаты в тесте:

1. `members_disjoint: sum(members) <= total + 1e-9` — кумтаймы
   членов; при вложенных вызовах членов перекрываются структурно,
   но на farstead ранний возврат фолдов держит их дизъюнктными;
   нагрузка не должна менять структуру вызовов (счётчики
   детерминированы).
2. `e04 clock_calls_per_beat >= 3.0` (измерено 3.19 на 2y) — запас
   мал, но это СЧЁТ вызовов (детерминирован).
3. Доли/учёт самосогласованы по построению (rest = total − sum).

Ни один кандидат не объясняет падение убедительно — потому KI
открыт, а не «исправлен». Ассерт-сообщение первого прогона было
обрезано (`tail -5`); при повторении — сохранить полный вывод.
