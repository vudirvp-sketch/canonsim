## B. Что исполнено (вторая половина вызова)

### B.1 Токены `:root` (+17)

```css
--font-body-family: "Inter", "Segoe UI", system-ui, sans-serif;
--font-mono: "SFMono-Regular", Consolas, monospace;
--font-root: 14px;            /* база — тоже токен */
--font-micro: 0.72rem;        /* state-теги, роли */
--font-meta: 0.78rem;         /* provenance, mono-мета, ноты */
--font-compact: 0.84rem;      /* плотные строки данных */
--font-body: 0.9rem;          /* рабочий текст */
--font-heading: 0.95rem;      /* h3-класс */
--font-heading-l: 1rem;       /* поверхностный h2 */
--font-heading-xl: 1.05rem;   /* app h1 */
--weight-strong: 600;
--tracking-label: 0.05em;
--radius-s: 4px;  --radius-m: 6px;  --radius-l: 8px;  --radius-pill: 999px;
```

### B.2 Замены (105 употреблений, счётчики заассерчены скриптом)

- **font-size ×51**: 14 органических значений → 7 шагов шкалы.
  Консолидация близнецов: 0.74→meta, 0.80→meta, 0.82/0.84/0.85→
  compact, 0.86/0.88→body, 0.92/0.95→heading. **Максимальный дрейф
  +0.04rem = 0.56px при корне 14px** — суб-пиксель (тот же прецедент
  формы, что V1: девять hex-литералов → шесть именованных токенов).
  Контекстное `0.92em` элемента `code` остаётся em-отношением —
  относительная метрика, не решение шкалы (закон V2 запрещает
  px/rem, не em).
- **border-radius ×27**: 3px поглощён `--radius-s` (1px на чипе
  кода); составные формы (`6px 6px 0 0`, `999px 0 0 999px`,
  `0 4px 4px 0`, `0 999px 999px 0`) переписаны на var()-выражения.
- **font-family ×13**: моно-стек из 13 копипаст → `var(--font-mono)`.
- **font-weight ×7**: `600` → `var(--weight-strong)`.
- **letter-spacing ×4**: 0.04/0.05/0.06em → `var(--tracking-label)`.

Трансформация исполнена персистентным скриптом со счётчиками
(ожидание≠факт → отказ записи): одна попытка до правки счётчиков
поймала собственную ошибку инвентаря — скрипт не записал файл.

### B.3 Guard V2 — исполняемый закон (tests/architecture/guard.test.ts)

Новый ряд сканирования той же формы, что V1: вне `:root` запрещены
сырые `font-size` (px/rem), `font-family`-стеки в кавычках, числовые
`font-weight`, `border-radius` с px (0 в составных формах легален —
семантика прямого угла). **Мутационная проверка** (канон iter-293/
297): три класса нарушений внесены в styles.css временно — V2 ушёл
в RED с перечислением всех трёх («expected […(3)] to deeply equal
[]»); файл восстановлен — GREEN. Guard теперь 10 тестов (9+1),
витест-счёт 221 → 222.

### B.4 Живая верификация computed-стилей (сильнее скриншот-диффа)

Headless Chromium над обслуживаемой композицией, чтение
`getComputedStyle`:

```json
{"root":"14px","body":"Inter, \"Segoe UI\", system-ui, sans-serif",
 "h1":"14.7px","code":"SFMono-Regular, Consolas, monospace",
 "codeRadius":"4px","button":"4px","note":"12.6px"}
```

Каждый токен резолвится в заявленное значение. Дополнительно:
«до»/«после» скриншоты всех семи поверхностей сняты (7+7 PNG,
приложены к сессии), ноль ошибок консоли после HMR-перезагрузки.

## C. Что сознательно НЕ вошло (границы ряда)

- **Шкала spacing** — 131 layout-влияющее объявление
  (padding/margin/gap) с 17 органическими значениями. Отложено как
  СЛЕДУЮЩИЙ визуальный ряд (§25 P2 продолжение): spacing меняет
  layout, а не только отрисовку — нужен собственный визуальный
  пруф-проход по поверхностям, не тихое подмешивание в этот ряд.
- Layout-максимумы одиночного употребления (980px, 216px rail,
  max-height 180/220/420px) — L13 (abstraction cost gate): литерал,
  употреблённый один раз, не «scatter», токенизация не окупается.
- Клавиатурные/focus-ряды, accessibility-базлайн (LAW §15) — свои
  owner-gated ряды (ux-1), не часть токен-ряда.

## D. Наблюдение ревизии (не дефект, вопрос дизайна)

наблюдение для решения владельца, НЕ изменено (scope discipline).
