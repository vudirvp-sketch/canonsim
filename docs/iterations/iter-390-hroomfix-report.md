## A. Что сделано

### A.1 Гипотеза первопричины — подтверждена чтением кода

Каждый H-вызов всей цепи m5/m6 шёл ОДНИМ user-сообщением:
`station_m6_probe.py` (h_cycle, run_det — все H-точки) и
`station_hroom.py` v2.0 (h_cycle_full, _run_det_h) строят
`[{"role": "user", "content": doc}]` — **system-роли не было
нигде**. Модель встречала документ вызова двери (ввод игрока,
грамматика, протокол + гибридный хвост) без всякой роли и задачи
и досывала форму ответа из протокольного хвоста как умела —
отсюда хвостовые ре-эмиссии формы, чеклисты и self-ноты ПОСЛЕ
готовой прозы: грамматика GBNF гарантирует структуру (вердикт,
пустая строка, проза-без-пустых-строк, финальная пустая строка,
EOS), но не СОДЕРЖАНИЕ строк прозы — мета-текст жил внутри
prose-строк и заканчивался естественной остановкой (все три
хвоста iter-389 — finish=stop, не потолок).

### A.2 Дельта 1 — THE H SYSTEM PROMPT (половина первопричины)

`HYBRID_SYSTEM_PROMPT` в station_hroom.py: роль (рассказчик
сцены), задача (один вызов — один ход), форма (JSON-вердикт по
протоколу → ровно одна пустая строка → проза 2–4 предложения на
языке реплики), и ЗАКОН ОСТАНОВКИ: ответ заканчивается финальной
пустой строкой — после неё НИЧЕГО (ни второго вердикта, ни
повтора формы, ни чеклиста, ни самопроверки, ни разделителя, ни
комментариев о собственном ответе). Едет в КАЖДЫЙ H-вызов через
`_hybrid_messages(doc)` — обе руки И det-датум (одна форма
байтами: чистая функция, одинаковые байты на каждый вызов — закон
юнита test_hybrid_messages_law).

### A.3 Дельта 2 — THE TAIL-BREAK (страховочная половина)

`_tail_break(prose)` — чистая функция: проза режется по САМОМУ
РАННЕМУ распознанному маркеру утечки. Маркеры — узкий список по
формам ИМЕННО прогона владельца iter-389:
`## HYBRID REPLY FORM` / `HYBRID REPLY FORM` (s2 ре-эмиссия + s8
чеклист), `JSON Verdict:` (s8 тело), `*(Self-Correction` /
`Self-Correction` / `Refinement Note` (s10 нота), `{"` (s2 второй
вердикт-JSON; голый объект никогда не открывает чистую прозу).
Каждый маркер едет со своей пунктуационной оградой (`## `, `*(`),
чтобы граница ложилась на начало строки заголовка — чистая проза
не оставляет клочков. Ограда `---` НЕПОСРЕДСТВЕННО перед маркером
уходит вместе с хвостом (это забор блока утечки, s10-форма);
голый `---` БЕЗ маркера после него НЕ трогается НИКОГДА — закон
«не слепого ---», вердикт владельца дословно. Голова-вердикт не
трогается вовсе (разрез только в prose-половине после сплита).

### A.4 Честность записей (clean/raw)

- `prose`/`prose_full` — ЧИСТАЯ поверхность (после отсечения);
  `prose_len` по чистой; классификация потолков — по чистой.
- `prose_raw` / `tail_cut` / `tail_marker` / `tail_cut_text` —
  улики дословно; замкнутое кольцо: `clean + cut_text == весь
  хвост` (rstrip-нутые переводы строк принадлежат вырезанному,
  ничего не теряется — закон, пойманный юнитами на первой
  итерации правки).
- Флаги `json_bleed`/`protocol_echo` читаются по СЫРОМУ хвосту —
  цензус утечек, а не косметика после отсечения.
- det-датум сравнивает ЧИСТЫЕ формы (`_hybrid_clean`), + поля
  `tail_cut1/2, tail_marker1/2` на каждый вызов.
- Отчёт: строка «meta-text tails cut (the H8 fix, v2.1)» на руку;
  THE TAIL-BREAK CENSUS (вырезанные хвосты дословно, первые 140
  знаков, с маркером и числом срезанных знаков); строка
  мета-хвостов в THE HEADROOM VERDICT.

### A.5 Юниты: 10 → 17 (все зелёные)

Семь новых законов — s2/s8/s10-формы прогона владельца
воспроизведены как тесты пака: s2 (форма + второй JSON: разрез по
форме, чистая проза сохранена, вся утечка дословно в cut_text);
s8 (чеклист); s10 («---»-ограда уходит с нотой, проза до неё
цела; + `_hybrid_clean` — голова не тронута); no-blind-cut
(голый `---` и чистый хвост не режутся никогда); earliest
(двойная утечка режется по раннему маркеру, поздняя едет в
cut_text нетронутой); форма вызова (системная роль открывает,
одинаковые байты); закон содержания промпта (роль/форма/СТОП/
запреты, без JSON). Прогон в песочнице: 17/17 + --help +
py_compile. Живая полоса — за владельцем (та же Gemma-4-E4B,
той же одной командой).
