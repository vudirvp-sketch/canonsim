на ~75 КБ (ячейка Consequence 61 071 символ + 70 строк продолжения с

### A.3 Зуб рецидива в docguard (R1)

Причина дрейфа устранена механически: `_DECISION_SECTION_RE = ^### D-` —
секции считаются в тот же кап 30 (сообщение теперь честно показывает
разбивку «N table rows + M post-table sections»), и проверка N017
(PCC-поля для R3+) распространена на секционную форму. Тест:
`test_decisions_section_entries_count_and_pcc` — crafted-breach на 33
записи (2 строки + 31 секция) + R3-тег в секции без PCC ловится, с PCC —
чисто. Обновлено утверждение старого теста `test_decisions_row_cap` под
новую форму сообщения. Это философия doc-3, применённая к её собственной
слепой зоне: кап не может снова молча расползтись.
