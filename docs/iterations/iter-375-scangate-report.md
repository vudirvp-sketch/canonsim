## B. Закон инвалидации (назван ПЕРВЫМ — вызов владельца)

Гейт-вердикт скана — функция ровно пяти входов: (1) `pack` —
парс-заморожен на руне; (2) `world` — рождён один раз (open/resume,
оба до любого бита), никогда не мутируется (`generate_world` чиста,
мид-ран записей нет); (3) `spec.probe` — замороженный shared
IntentData (закон разделения iter-370: frozen+slots, пути мутации
нет); (4) `spec.requires` — парс-замороженный кортеж; (5) значения
проекции на ОБЪЯВЛЕННОМ НАБОРЕ ЧТЕНИЙ спеки
(`precondition_read_pairs` — occ-1 близнец, суперприближение по
построению; закон индекса occ-1: согласные пары чтения отвечают
`first_failing` идентично — фальсифицирован живьём
twin-agreement-законом, tests/test_occidx.py).

**Ключ ЕСТЬ инвалидация**: скан перечитывает пары каждый вызов,
равный ключ ⇒вердикт не мог двинуться. Никаких счётчиков версий,
коммит-хуков, предположений о порядке — окна устаревания нет по
построению. Идентичность (pack, world) штампуется в рождении таблицы
и перепроверяется на каждом скане (`bind` — чужой объект смывает
таблицу; защита от любого будущего паттерна вызова). Оконное
семейство НИКОГДА не мемоизируется: парс кладёт `pairs=None` для
спеков, чьи requires читают временные свёртки — fence скипа
(fold-demand) стал законом СЕМЕЙСТВА, не только лупа: гейт-пак
держит точную по-стретч-оценку даже под мемо-вызывающего.

## C. Изменение (5 файлов кода + 4 тест-файла)

1. **`core/intent.py`** — `ScanGateMemo` (bind/lookup/store,
   `__slots__`; домен одного (pack, world)) + `pair_values`
   (строитель ключа: живые значения по парам, порядок парс-константен)
   — рядом с `precondition_read_pairs`, единый владелец закона
   индекса.
2. **`core/urgencies.py`** — `_UrgencySpec.pairs` (parse-время:
   отсортированный read-set для негейт-оконных requires, None иначе)
   + `urgency_scan(gate_memo=None)`: гейт-ветка консультирует мемо,
   None (дефолт) держит свежую оценку — все прежние вызывающие не
   тронуты.
3. **`core/factions.py`** — двойник (то же поле, тот же parse, тот же
   параметр скана; семейный закон — urgency-форма).
4. **`core/loop.py`** — `self._gate_memo` (рождён с пачкой лупа,
   мир биндится на первом скане) + проводка в оба скана
   `_skip_quiet_beats`.
5. **`core/knowledge.py`** — **ленивая насыщенность**: eager-счётчик
   новизны `(teller, listener)` (O(знающих) на запись: birth-init +
   bump + декремент-обходы, K² пар) УДАЛЁН; его единственный
   потребитель — zero-тест `_novel_facts` — заменён предикатом
   `saturated(teller, listener)`: множество токенов рассказчика
   ⊆ множеству токенов слушателя (P7 append-only делает обе половины
   монотонными — подмножество отвечает zero-тесту счётчика ТОЧНО,
   перечитывается свежо, обслуживания ноль). `_rows_by_token` и
   `_token_holders` жили только ради счётчика — удалены вместе с ним;
   новый `_tokens` (знающий → множество токенов строк) — O(1) на
   запись.

## G. Эвиденциальная заметка (farthest-md5 iter-370, не KI)

D-253 цитирует farthest-конверт как «farstead 100y … md5
`4adcd95b…`, 0.37→0.33 с, события 1350». Под номинальными
параметрами (100y сегментированные, seed 7, loc_square) этот прогон
не воспроизводится: события 13 915 (точно строка iter-362 — его
собственный farstead-конверт 4.48→3.28 с на тех же 13 915),
md5 `4e4f4cf2…`. Ни одна опробованная форма (10y/100y ×
whole/segmented) не даёт 1350 событий. Запись iter-370, вероятно,
смешала параметры (0.37 с — это стена h3 10y этой же сессии);
байты `4adcd95b…` невосстановимы из записей. Действие: мой конверт
заякорен на форму iter-362 с сессионной локальной идентичностью
до/после; строка D-253 не правится (не могу доказать ошибку — только
невоспроизводимость). Если владелец узнает форму — одна команда
закроет вопрос.

## H. Риски и честные границы

1. **Общая таблица между семействами**: memo лупа одна на оба скана;
   ключи — probe.id (`urgency_NNNN` / `faction_NNNN` — префиксы не
   коллидируют); идентичность (pack, world) смывает при любом
   переходе.
2. **Списочные значения в ключе**: сравнение == поэлементно (как
   читал бы first_failing); ключи никогда не хешируются (dict-ключ —
   probe.id).
3. **`saturated` по определению**: закон — подмножество ≡ нулевой
   счёт (P7-монотонность); фальсификаторы — грубая сила на синтетике
   и на реальном логе. Старый счётчик не сохранился ни в одном
   API-поверхности (единственный потребитель был zero-тест).
4. **Resume**: мемо runtime-only, не входит в cursor-state; новый
   Simulator ⇒ холодная таблица ⇒ корректно по построению
   (run-state export/restore не тронуты).
