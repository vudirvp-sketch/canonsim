## A. Что сделано

### A.1 Вопрос и его арифметика (аналитическое чтение m5)

Прогон m5 (iter-366 §B.3) поднял вопрос: обе гибридные руки упёрлись
в HYBRID_MAX_TOKENS=416 ровно по разу (h0 s7cy0, h8 s8cy2,
finish=length, ctok=416) при естественной медиане 84/85 токенов —
«вопрос запаса токенов пака v5.1, не дефект закона». Арифметика
записанных чисел уже несла сигнатуру: хвосты 581/658 знаков при
бюджете ~386-396 хвостовых токенов (416 минус компактная JSON-голова
~20-30) — это ~1.5-1.7 зн/ток против 3.5-4.5 у чистой английской
прозы на гемма-классе токенизаторов, т.е. вырожденное токен-сжигание
(класс json-bleed-хвоста, который m5 ЗАПИСАЛ живьём: кодовая ограда с
повторной эмиссией вердикта), не голодание легитимной прозы. Но хвосты
не были записаны целиком и не были классифицированы — вопрос стоял
открытым. Закрывает его только измерение на производственной модели —
инструментом, которому можно верить. Инструмент построен и
валидирован.

### A.2 Инструмент: station_hroom v1.0 (внешний пак, Правило 9)

`station_hroom.py` (+ .bat + README_RU.txt; исходник в
docs/station/archive/canonsim_hroom_pack_v1.0.zip, 3 файла): гибридное
ядро m5 ПОСЛОВНО — механика ИМПОРТИРУЕТСЯ из m6-пака (закон соседних
паков; прецедент: сам m6 импортирует station_m5_doctor), никогда не
перестраивается: Battery/ParserDoor/гибридная грамматика/хил-лестница/
рецикл через 20 вызовов/возобновление построчно/always-a-zip. Ровно
ДВЕ дельты против m5-ядра (печатаются на старте):

1. **ПОТОЛООК**: генерация на `--cap 832` (2×416) — естественный
   конец каждой строки наблюдаем; ПРОИЗВОДСТВЕННЫЙ 416-ВИД ВЫВОДИТСЯ
   ТОЧНО: поток токенов с фиксированным сидом одинаков под любым
   потолком (потолок только обрезает, никогда не меняет предыдущие
   токены) — строка с естественной остановкой N<=416 при 416 не
   тронута, строка пробежавшая 416 — производственное усечение;
2. **АДДИТИВНЫЕ ЗАПИСИ**: prose_full (весь хвост — m5 несла первые
   600 знаков: достаточно для леджера m3, недостаточно для
   классификации и эстетического чтения именно длинных строк) +
   head_chars (длина JSON-головы, для арифметики зн/ток).

Классификатор потолочных хвостов — четыре вердикта с приоритетом
LOOP > BLEED > BURN > LEGIT: LOOP = хвостовое слово-n-грамм-повторение
(r>=3) ИЛИ коллапс словаря (<0.35 уникальных/всех); BLEED = флаги
json_bleed/protocol_echo (m3-формы); BURN = хвост <2.2 зн/ток или
JSON-голова, съевшая весь бюджет (пустой хвост); LEGIT = чистый
длинный хвост — единственный класс, который потолок реально чинит.
Гроссбух: распределение естественных ctok (min/p25/med/p75/p90/max),
производный 416-вид, построчные вердикты с уликами, стены (медиана/
макс; цена потолочных строк против медианы руки).

### A.3 Живая валидация — ЗУБЫ, счёт в счёт с независимо записанным датумом

Полный корпус (10 юнитов / 42 say-цикла × h0+h8, корпус — собственный
коммит-фикстур репо tests/fixtures/parse_replies.json) на ультралайт-
полосе валидации iter-365: llama.cpp **b11541 ubuntu-x64** (пин паков,
тот же билд, commit f2918cabb) + **Qwen3-0.6B-Q4_K_M** (файл доктора),
CPU 2 ядра, декод ~15.5 ток/с. Результат (hroom_20261014_131228.zip,
полные jsonl обеих рук + reference + отчёт + лог сервера):

| метрика | h0 (temp 0) | h8 (temp 0.8-seeded) |
|---|---|---|
| естественные остановки | **34/42** | **41/42** |
| естественный ctok med / p90 / max | 66 / 114 / 138 | 52 / 103 / 146 |
| потолочные (cap 832) | **8** — LOOP 5, BURN 3 | **1** — LOOP 1 |
| 416-вид (производный) | **0** естественных над 416 | **0** |
| LEGIT (потолок бы чинил) | **0** | **0** |
| стены med / потолочные med | 9.0 / 76.3 с | 6.8 / 75.1 с |

**ЗУБЫ:** счёт h0 8/42 потолочных — В ТОЧНОСТИ датум iter-365 (8/42
finish=length на той же полосе, sandbox-отчёт m5); h8 41/42 + 1 —
В ТОЧНОСТИ датум iter-365 (41/42 stop, 1 length). Инструмент не
только воспроизводит независимо записанный результат — он его
РАСКЛАССИФИЦИРОВАЛ: все 9 хвостов вырожденные, ноль LEGIT. Улики:
коллапс словаря 0.02-0.05 (13-31 уникальных на 599-718 слов);
аттракторы «loc_tavern. The player has looked around the»×9,
«A blank line.»×21 (модель заучила разделитель протокола как литерал
— родня «The verdict is that...» из iter-365); три head-burn —
JSON-голова не закрылась, бюджет съеден без единой пустой строки.
Вердикт полосы: **416 — не отсутствующий запас; каждое упирание —
вырожденный хвост, который подъём потолка не чинит (класс фикса —
ломатель хвостов или принять-и-пометить); цена вырожденных строк ~8×

## D. Риски

- **Полоса ≠ продакшн**: 0.6B-CPU-датум — ВАЛИДАЦИЯ инструмента
  (зубы против известного результата), не производственный ответ;
  производственное распределение снимает станционный прогон тем же
  паком (Gemma-4-E4B). Отчёт несёт бенд/билд/модель в шапке.
- **Недетерминированность повторных вызовов** (m5 det-h: temp-0
  identical=False на повторном вызове с грамматикой) — инструмент
  гоняет каждую строку ОДИН раз; производный 416-вид точен ВНУТРИ
  вызова по построению; сравнение между руками/полосами — классами,
  не байтами.
- **Оценка head-токенов** (3.8 зн/ток компактного JSON) — оценка;
  вердикты LOOP/BLEED от неё не зависят (коллапс словаря и флаги —
  прямые улики), BURN устойчив (порог 2.2 против чистых 3.5-4.5).
- **Счётчики llama-server** не переносятся между полосами — стены
  записаны как CPU-полоса (15.5 ток/с декод), станция снимет свою.
