## B. Законы, которые несёт поверхность

- **Замыкание §8 как ступени, никогда не коллапс.** Черновик — это
  REQUEST (маркер DRAFT), никогда не утверждение эффективного
  состояния (`input.value !== EFFECTIVE` — запрещённый коллапс
  назван и сфальсифицирован тестом). Сохранение — ОДИН явный
  диспатч. На ACCEPTED возвращённый документ — новая наблюдаемая
  база, и черновик согласуется с **ответом сервера**, никогда с
  локальной проекцией (тест: после save чекбокс следует документу
  ответа, а не значению черновика до отправки). EFFECTIVE —
  собственный закон стора, дословно: `applies: next-spawn`, живой
  сервер держит свои флаги до выгрузки (note выводится verbatim при
  `managed_live`). Превью команды — read-only, вью компоновочного
  корня (§18), никогда не вычисляется клиентом.
- **Закрытый набор и «громкие» отказы.** Сохранение шлёт только
  изменённые поля (закон partial стора: отсутствующие поля не
  тронуты — фальсификатор в тесте: тело диспатча несёт ТОЛЬКО
  `no_webui: false`). Отказ рендерится verbatim с причиной шлюза:
  неизвестное поле («unknown field(s) ['threads'] (closed set:
  [...])»), чужой тип («no_webui 'yes' must be a bool»), READ без
  аргументов («takes no arguments»), session-scoped закон без
  сессии. Черновик при отказе СОХРАНЁН — решение за пользователем.
- **G4 без автоповторов.** Каждая явная попытка — свежий
  idempotency-ключ (фальсификатор в тесте: два сохранения — два
  разных ключа). Транспортный сбой после отправки оставляет исход
  UNKNOWN — полоса честно говорит это и НЕ повторяет; перечитывание
  — явное примирение пользователем.
- **Без поллинга.** Монтировка = РОВНО ОДИН READ (прецедент S0-1
  GatewayStatus; тест: один диспатч и через 40 мс остаётся один).
  Настройки не меняются под читателем.
- **Session-scoped закон.** READ без сессии работает всегда; без
  сессии Save честно выключен с маркером «no session — save
  disabled» (тест: session-scoped диспатч никогда не уходит).
- **Канал CONFIG.** Панель маркирована `CONFIG · USER` (тест пинит
  отсутствие LIVE/HISTORY тегов) — третий мир после LIVE-хвоста и
  HISTORY-логов.

## E. Риски

- Фикстура `backend_settings_update_ok` снята с partial
  `{no_webui: false}` — конкретное значение не особенность контракта
  (контракт — форма документа); переснять с другим partial тривиально.
- `command_preview` в фикстурах содержит полную скомпилированную
  команду из дефолтов инференс-профиля на момент снятия — при смене
  дефолтов профиля фикстура переснимется (форма контракта неизменна;
  это же обычай observatory-фикстур).
- Тест REJECTED-полосы сохранения подаёт canned-причину bad-type —
  этот клиент такой тип никогда не пошлёт (типы закрыты на уровне
  компиляции), полоса сфальсифицирована как harness-качество, живой
  smoke закрывает её настоящим проводом.
