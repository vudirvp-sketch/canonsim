## B. Законы, которые несёт поверхность

- **Dual-read (§4), на обоих уровнях.** Панель маркирована
  `HISTORY · COMMITTED LOGS` (тест пинит отсутствие LIVE-тега) и
  **на уровне провода** пинита: каждый диспатч — только
  `observatory.*`, `session.events` не вызывается никогда —
  фальсификатор закона, а не декларация.
- **Ограниченность (§6).** ОДНО окно в памяти (≤ 200 строк —
  потолок бэкенда); пагинация вперёд ЗАМЕНЯЕТ окно (тест: после
  перехода в DOM 5 строк, не 55; клиент никогда не материализует
  прогон). Виртуализация не нужна — механизм ограниченности сам
  серверный потолок окна, и это заявлено.
- **Семантический курсор.** `after` — id события (фальсификатор в
  тесте: тело второго диспатча несёт `after: "ev_0049"`, никогда
  индекс строки); `next_after=null` — конец прогона, кнопка
  честно выключена.
- **Грамматика пустых состояний (§9).** NO DATA (корень без
  прогонов) ≠ NO MATCH (прогона нет — причина DOMAIN_REJECTED
  дословно) ≠ STALE CURSOR (id выпал из прогона — дословно +
  ЯВНЫЙ «перечитать с головы», решение пользователя, G4: ноль
  автоматических вторых диспатчей) ≠ TRANSPORT ≠ MISMATCH. Каждая
  — своя полоса, никогда «пустое окно» взамен отказа.
- **Без поллинга.** Смонтированная панель не делает НИ ОДНОГО
  диспатча (тест) — прочная история не меняется под читателем,
  каждое чтение явно. Инспектор ест ТОТ ЖЕ документ (LAW §5.1,
  тест: число диспатчей не растёт от выбора строки).
- **Строка идентичности (§9).** Контекст-стрип: run / seed / pack
  / profile `CANON_VIEW` / authority `CANONICAL` / 50/56 / окно /
  бейдж DURABLE.

- Тест полосы stale-cursor в браузерном бэнде подаёт консервную
  причину (снятую с after=ev_9999) на переход после=ev_0049 —
  несоответствие материала и сценария в jsdom-бэнде; живой smoke

  переснять с матчащим `after`.
- Бесконечной прокрутки назад нет (только «перечитать с головы»)
  — осознанный boundedness-выбор, заявлен в UI, не дефект.
