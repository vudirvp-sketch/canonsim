## B. Четыре решения владельца — где живут

1. **M4 = жёсткий канон.** Никакого пути recovery/dispute для
   ошибочно-заккоммиченных модельных действий — никогда.
   Необратимость INV-5 — стоящая форма; retcon потребовал бы нового
   owner-gated дизайна (отклонено этим вызовом). Закреплено в строке
   `auth-1` (её acceptance прямо исключает recovery) + в §6-записи.
2. **Нарратор = L12 прямо сейчас (production-форма).** Записано в
   `docs/PRESENTATION_SPEC.md` §7: честный потолок (56 битов / 168
   вызовов / ноль принятых на 4B/9B/12B/27B-IQ3_XXS); тяжёлая рука
   открывается ТОЛЬКО за закрытыми контрактами (sem-1/auth-1/
   speech-1), никогда как параллельная надежда. Фрейминг владельца
   закреплён рядом: production-форма = симуляторный промпт-контракт
   (снапшот/brief IR + системный/ситуационный промпт — кто модель,
   что делает, как озвучивает), качество прозы — дело МОДЕЛИ (модель
   + настройки + промпт); L12 — детерминированный пол. Это в точности
   приземлённая архитектура (контракт сериализатора §2 + дверь
   медиатора), теперь как заявленное намерение.
3. **Без фиксированного рамочного бюджета времени.** Работа строится
   по готовности: модели и настройки у всех разные; бюджет —
   НАБЛЮДАЕМОЕ свойство развёртывания, никогда не цель репо.
   Фиксированный вопрос M3 растворён (измеренные числа остаются
   данными: 27B 3.8–6.1 с на вызов generate, репо-сторона ~4 мс).
   Отражено в §6-записи + STATUS Next.
4. **Liveness/emergence (C24/C27) — PARKED.** Не трогать до закрытия
   sem-1/auth-1/scale-1; затем — измерять, а не «добавлять
   интересность». Отражено в §6-записи + STATUS Next.
