## A. Вердикт: перенимаем МЕТОД, не власть

Документ выдерживает проверку законами репо: он сам отказывается
быть вторым авторитетом (его §0.2/§1.3/§34), сам роутит остаток в
существующих владельцев (его §31) и сам закрывает типовую болезнь —
«внешние референсы молча становятся властью или усредняются в
AI-сlop». Это ровно та ниша, где CanonSim не имеет своей
дисциплины: законы владеют ПРОДУКТОМ (что строим), метод владеет
ИССЛЕДОВАНИЕМ (как решаем, когда внешний референс влияет на
дизайн-решение).

## B. Что перенимаем (durable residue)

| # | Механизм | Суть |
|---|---|---|
| 1 | Наблюдение до интерпретации | сначала наблюдаемое («стабильная зона действий», «неканальный state-признак»), потом прилагательные; «чище/премиальнее» — не доказательство |
| 2 | Механизм, не внешний вид | переносимая единица = механизм + функция + граница; никогда палитра/анатомия страницы/форма компонента |
| 3 | Граница переноса (transfer boundary) | каждый перенос называет, что ОСТАВАЕТСЯ у донора (навигация, лейблы, стили, фреймворк, словарь) |
| 4 | Целевой конверт (target envelope) | референс — эксEMPLар, не пиксель-команда: MUST PRESERVE vs MAY VARY; конверт обязан пережить кириллицу, длинные лейблы, loading/stale/failed, мульти-таб |
| 5 | Claim → Falsifier → Evidence | утверждение + наблюдение-опровержение + доказательство (static/runtime/task/performance — классы не смешиваются) + disposition (KEEP/MODIFY/BOUND/DEFER/REJECT) |

Плюс: лестница глубины исследования по риску (direct build → light →
standard → deep — ритуальных квот нет), анти-усреднение (один
primary-референс, ограниченные вторичные), anti-slop-вопросы («какое
свойство CanonSim это мотивирует? переживёт ли идентичность удаление
декорации?»), VIS-0..3 (классификация визуальных дефектов — только
визуальных, не замена P0–P4), компактная форма записи переноса (§27
документа) — едет в отчёт владеющей итерации.

## D. Что НЕ перенимаем (отказы §34 документа — теперь наши)

- Параллельная Refero-власть любого вида: дерево/реестр/токены/
  библиотека компонентов/proof-фреймворк — НЕТ.
- Глобальный документ Reference Lock — НЕТ (row-local коммитмент
  внутри задачи — ДА).
- Квота новизны («одна запоминающаяся деталь») — НЕТ.
- Обязательный мульти-источниковый ритуал/счётчики запросов — НЕТ.
- Pixel-perfect визуальный гейт — НЕТ (целевой конверт сильнее).
- Refero как runtime-зависимость — НЕТ.
- Палитры/типографика/компоненты донора как CanonSim-токены — НЕТ.

## E. Почему это честно по законам репо

- D-024 (один факт — один владелец): метод едет ТОЛЬКО в
  агентский контекст трека; продуктовые законы (UIUX_LAW,
  VISUAL_SYSTEM_UI, WORKBENCH_APP_LAW…) не тронуты ни строкой.
- Прецеденты соблюдены: форма iter-288 (ingest → distill → archive)
  + форма ssi-2 (read-only-copy в allowlist docguard).
- §8 AGENTS (допуск новой агентской машинерии): named consumer =
  веб-трек; demonstrated problem = внешний референс без дисциплины;
  minimal intervention = §9 + архив; scope safety = ноль вторых
  источников истины.
- INV-1..5 не тронуты: ноль кода, ноль канона, LOG нетронут.
