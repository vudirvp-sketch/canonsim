## B. Инженерные решения (почему так)

- **Инструмент — существующий vitest-сьют**, ноль новых
  зависимостей. AGENTS §2.8: существующий механизм → минимальное
  расширение → новая машинерия. Это же паритет формы с бэкендом:
  INV-4 там исполняет `tests/test_architecture.py` (тест, не
  линтер). dependency-cruiser / eslint-boundaries и Playwright-smoke
  остаются запаркованными строками со своими допусками — их час
  придёт, когда граф импортов перерастёт guard-тест.
- **Скан — call-form паттерны** (`fetch(`, `localStorage.`), а не
  голые идентификаторы: докстринги, пересказывающие закон («no
  component ever sees fetch», «Nothing here ever touches
  localStorage»), не дают ложных срабатываний — документация не
  есть использование.
- **Точка отсчёта — `process.cwd()`** (npm-скрипты всегда исполняются
  из корня пакета, лаунчер гонит тот же npm); при запуске из другого
  места guard падает громко, а не сканирует чужое дерево.

## C. Мутационная проверка (claim → falsifier → evidence)

Свежепринятый метод (D-246) применён в ту же сессию:

- **CLAIM**: guard исполняет законы.
- **FALSIFIER**: незаконный модуль должен покраснить тест.
- **EVIDENCE**: вброшены два зонда —
  `localStorage.getItem` в features/trajectory (R3) и кросс-фича
  импорт gateway-status → trajectory/useLiveTail (R5). Оба пойманы
  RED с файлом+строкой+цитатой; после удаления зондов — снова
  зелёный. Guard доказал, что не декорация.
