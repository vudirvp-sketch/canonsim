## B. Развилка дизайна (D-198 §2.7 — синтез перед выбором)

Кандидаты:

- **(A) Чисто читающая мемоизация ключа**: кеш «последний ключ»
  сравнивается с живыми значениями — сравнение СТОИТ столько же,
  сколько сборка (это и есть чтение). Отклонён по построению.
- **(B) Глобальный счётчик версий проекции**: любая закоммиченная
  запись инвалидирует ВСЁ — зерно инвалидации «весь мир», счёт
  ре-эвалов взлетает с 508 до порядка событий×спеков (25 859 × 123).
  Хуже статус-кво на частых событиях. Отклонён.
- **(C) Коммит-фолд пар (форма-кандидат STATUS)**: инвертированный
  индекс объявленная-пара → читающие зонды; запись в объявленную
  пару ВЫТАЛКИВАЕТ подтверждённых читателей; чтение O(1) на спек
  (гейт + дикт-гет вердикта); зерно инвалидации = ПАРА — честный
  минимум, который лицензирует закон occ-1 (вердикт — функция
  значений на объявленных парах, и ТОЛЬКО их).
- **(D) Теневые значения пар на коммит-пути**: pair_values читает
  тень (1 гет вместо 2) — коэффициент, а не срез члена; компар
  ключей остаётся. Отклонён как полумера.
- **Синтез (C)** удовлетворяет объединению преимуществ ((A) ноль
  цены на коммите при (C) ~нуле — O(1) frozenset-гет + редкие
  попы; (B) O(1) на проход при (C) O(1) на спек без
  все-мир-инвалидации) и устраняет материальные недостатки обоих.
  **Эмерджентное свойство, названное и проверенное: ЗАКОН SERVE**
  — фаст-путь подаёт РОВНО тот вердикт, который дал бы компар
  ключа, никогда больше; это не украшение — именно он делает
  законы-оракулы записываемыми как законы РАВЕНСТВА
  (fold-скан == мемо-скан == свежий скан), а не обещания.

## C. Изменение (4 файла кода + 1 новый тест)

1. **`core/intent.py` — `ScanGateFold`** (рядом с `ScanGateMemo`,
   единый владелец закона индекса occ-1): declared map (probe →
   пары; объединение ОБЕИХ семейств — urgency/faction; оконные и
   негейтованные спеки `pairs=None` не входят) + readers inversion
   (пара → читающие зонды); **ЗАКОН POP**: `apply_change(entity,
   prop)` (двойник apply_event, вызывается из `_commit` на каждую
   запись) выталкивает подтверждённых читателей пары —
   консервативно: значение, вернувшееся назад, ре-хитит
   сохранённый ключ на следующем скане (одна лишняя сборка, никогда
   неверный ответ); **ЗАКОН SERVE — три O(1)-гейта**: (i)
   идентичность `serves` (объект проекции, форма
   SensesIndex/RollIndex), (ii) DECLARED (`confirm` допускает
   только своё (probe, пары) из рождения — крафтящийся спек с
   коллидирующим id никогда не подтверждается), (iii) STAMP (фолд
   помнит ОБЪЕКТ записи мемо, который валидировал; всякий `store`
   и всякий `bind`-флеш заменяет объект — компар идентичности
   падает, бежит компар ключа: подменённая запись никогда не
   подаётся устаревшей). **Рождение читает НОЛЬ значений
   проекции**: фолд следит за ВРЕМЕНАМИ изменений, не за
   значениями — вердикты принадлежат мемо (рождается холодной),
   первый проход скана всё оценивает свежо; KI#16 (целая проекция)
   сюда не доходит. INV-1 лицензирует эквивалентность: проекция
   движется только через `_commit`, `_commit` фолдит каждую запись
   — «ни одна объявленная пара не менялась с подтверждения» ЕСТЬ
   «сохранённый ключ равен живым значениям»; закон occ-1 доводит
   до равенства вердиктов.
2. **`ScanGateMemo.answer` / `.entry_at`** — два новых однострочных
   аксессора: вердикт без компара ключа (None = записи нет —
   это заграждение, не вердикт) и объект записи (штамп, только
   идентичность). Владелец вердикта — мемо (D-024).
3. **Оба скана** (`urgency_scan`, `faction_scan`): keyword-only
   `gate_fold=None` (дефолт — компар ключа, все прежние вызывающие
   не тронуты); подтверждённый зонд пропускает `pair_values` и
   читает сохранённый вердикт; после store/lookup-hit — `confirm`.
4. **`core/loop.py`**: рождение из обеих семей спецификаций
   (генератор (probe.id, pairs) над `(*urgency_specs,
   *faction_specs)`) + re-birth при resume (перестраиваем — в
   export_run_state не входит) + фолд-строка в `_commit` (после
   RollIndex) + оба места вызова в `_skip_quiet_beats`.
5. **`scripts/labrunner.py`**: комментарий члена skip_probes
   (pair_values — честное отсутствие в профиле теперь).

## D. Законы-оракулы (tests/test_gatefold.py — 10, все зелёные)

1. **Рождение**: declared map + readers inversion на ВСЕХ шести
   коммитнутых паках (объединение семейств; оконные/негейтованные
   вне; пустой фолд — 68a-паттерн).
2. **ЗАКОН SERVE на уровне функций** (главный оракул): fresh ==
   memo == memo+fold на каждом паке с гейтованными спеками, по
   каждой форме скоупа — ответы, first_fire И порядок вставки
   dict'ов; тёплый фолд реально ПОДАЁТ (confirmed непуст, каждая
   запись несёт свои пары).
3. **Батарея внутри/вне по СВЯЗАННОЙ проекции** (честный
   продакшн-путь: apply_event + фолд в порядке _commit): вне —
   ни одного попа, множество confirmed держится; внутри — каждая
   достигнутая пара выталкивает и ре-деривит; флип-бэк
   ре-подтверждает.
4. **Фолд-двойник по всем классам краёв**: движение, не-объявленная
   запись (нуль попа), та-же-значение запись (поп + ре-хит),
   флип-бэк, две объявленные записи в одном событии, отсутствие
   (рождение пары, которой не было — на уровне самого фолда:
   времена, не значения).
5. **Штамп-гейт**: коллидирующий store под чужим ключом заменяет
   запись — фолд отказываёт (компар идентичности), скан отвечает
   свежему; bind-флеш — тем же путём (answer None → заграждение).
6. **Идентичность + чистота**: чужая копия проекции не
   обслуживается (компар ключа отвечает — закон мемо не
   испорчен); свежий парс спеков (specs=None) ОБСЛУЖИВАЕТСЯ —
   контент, не идентичность объекта.
7. **Declared-гейт**: крафт-спек с реальным id, но чужими парами
   никогда не подтверждается.
8. **Фракционный двойник** (crafted-пак итерации iter-375):
   внутри/вне + связанный поп.
9. **Реальный лог (провинция)**: p=100 ходок — живые position-пары
   (объявленные пары провинции — позиции!) выталкивают читателей
   на каждом ходе; двойник mid-run и на дренировании.
10. **Резюм-закон**: перевыпущенный фолд обслуживает
    восстановленную проекцию, двойник через дальнейшую игру
    (холодное мемо наполняется первым проходом).
