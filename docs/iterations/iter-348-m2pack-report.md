## A. Что сделано

### A.1 Пак `canonsim_m2_station_pack_v1.zip` (4 файла, 30 813 байт, md5 `1eb48a37…`)

1. **station_m2_probe.py** — станционная батарея. Руки (каждая
   — полный проход 51-utterance корпуса через НАСТОЯЩИЕ двери
   репо: Simulator + Mediator + ParserDoor на одном SceneLedger,
   narrator-половина детерминированно запинена корпусом — форма
   iter-312):
   - **A baseline** — форма §8.5 байт-в-байт (документ вызова и
     грамматика репо, canon-target ::= ID-перечисление).
     Контрольная строка батареи;
   - **B surface-enum** — грамматика с перечислением ИМЁН вместо
     ID (единственная правка документа вызова — одна строка
     протокола, заявленный фактор руки), нормализатор имя→ID
     точный (биекция имён проверяется в preflight);
   - **C free-target** — canon-target ::= string (любая строка) +
     детерминированный каскад нормализации: точный ID → точное
     имя → casefold → артикль-срез → уникальная подстрока →
     уникальный levenshtein≤2 (`--norm-levenshtein`). Отказ
     (промах/неоднозначность) — путь вопроса, никогда догадка;
   - **L leak-watch** — семьи F3 (ghost-существа) + F6 (инъекции)
     deviation-корпуса под всеми руками: F3 под C — ghost либо
     отказан (честно), либо РАЗРЕШЁН каскадом (LEAK — фальсификатор
     политики «без роста canon leakage»); под A ghost структурно
     невозможен (меряется собственная догадка модели в canon —
     базовая guess-линия);
   - **D determinism-mini** — greedy t0 ×3 + seeded t0.8
     один-сид ×3 + cacheless t0 ×3 + рестарт (спавн-форма);
     холод/тепло раздельно (см. B.4).
2. **Параллельные датумы** (подготовленные идеи, ехали бесплатно,
   оба — из STATUS Next «remaining owner calls»): **premise-drift
   статус** (причина battery_bug round-8, iter-314 §D — каждая
   рука сверяет состояние мира на СТАРТЕ цикла с
   референс-проходом; census отчётен RAW и CLEAN) + **split-колонки
   iter-312** (brief/parse/tick/generate через делегирующий прокси
   над run_steps).
3. **m2_analysis.py** — станционный разбор (таблица рук RAW/CLEAN,
   дельты против A, шаги нормализатора, leak-таблица, детерминизм,
   split-колонки, честное чтение — без решения: решение за
   владельцем, гейт runtime-promotion).
4. **station_m2_probe.bat + README_RU.txt** — форма
   станционных паков (запуск, параметры, ожидания, память,
   troubleshooting).

Инженерия зонда: attach- и спавн-формы движка (спавн владеет
жизненным циклом llama-server, рестарт-рука для детерминизма),
`--run-dir` возобновление (стадии пишутся в папку, готовые

## B. Сэндбокс-валидация: датумы (класс §13.1 — механика, НЕ станционная строка)

### B.1 Контрольная рука A заякорена к леджеру

Рука A воспроизвела строку **iter-312 engine1-q1p7b ТОЧНО**:
census 4 full / 15 kind / 32 mismatch (моя разбивка: 4 full +
15 kind + 16 target + 2 fields + 14 no_pin = 32 «mismatch» их
словаря), mix 51/0/0 — на ДРУГОМ билде (b11500 против b11337),
другом контексте (-c 2048 -np 1), той же модели/сиде/корпусе.
Кросс-билдовая воспроизводимость полосы через Census — самый
сильный якорь, который батарея могла получить: любое расхождение
руки A со строкой леджера на станции сразу сигналит о сдвиге
поверхности.

### B.2 Первые A/B/C числа полосы 1.7B CPU

| census RAW (51) | full | kind | target | fields | no_pin | drift |
|---|---|---|---|---|---|---|
| A baseline | 4 | 15 | 16 | 2 | 14 | 36 |
| B surface-enum | 4 | 17 | 14 | 2 | 14 | 40 |
| C free-target | 5 | 16 | 14 | 2 | 14 | 33 |

CLEAN (без premise-drift): A 2/15 · B 1/11 · C 3/18. Чтение
полосы (механика, не решение): **имя-vs-ID (B−A) = +0** — форма
ID не хуже имён на этой полосе; **каскад (C−A) = +1** при нулевых
отказах нормализатора; нормализатор: B 51/51 через точное имя,
C 51/51 через точный ID (полоса послушно эхом повторяет ID —
свободные surface-ссылки не упражнялись, norm_refused 0; полосы
крупнее могут вести себя иначе — E4B исторически догадывался
ghost-имена). **Экономический датум руки B**: generate p50
25.1 с против 9.9 с у A/C — литералы имён в грамматике стоят
~2.5× generate на CPU-полосе (constrained decoding по длинным
литералам); на GPU-полосе цена будет другой — датум едет с
батареей.

### B.3 Leak-watch на полосе 1.7B

F3: 6/6 «догадка в canon» у ВСЕХ рук (модель сама маппит
ghost-фразы в canon-существа — профиль aggressive mapper, тот же
класс что E4B round-4); **LEAK 0** — фальсификатор каскада не
выстрелил: полоса не эмитит свободных ghost-ссылок. F6: 2 payload
(steal-commit форма — прецедент f6c) / 4 legit / 0 declined.
Фальсификатор armed и ждёт полосу, которая эмитит свободные
ссылки — станционные полосы первые кандидаты.

### B.4 Детерминизм-мини: холод/тепло раздельно (новый датум b11500)

greedy t0: **холодный (первый) вызов ≠ тёплые (2-3)** (два
различных валидных ответа), тёплые идентичны; seeded один-сид ×3
идентичны; **cacheless ×3 идентичны**; рестарт воспроизводит
ХОЛОДНЫЙ вызов. Картинка когерентна: детерминизм держится ВНУТРИ
режима (холод/тепло/cacheless), между режимами форма батча меняет
порядок редукций — против b11337 (greedy 5/5 при живом кэше,
iter-312) это регрессия билда, честно записанная как датум
инструмента (два вердикта, не один). D3 seeded-local ярус держится.

### B.5 Грамматический пин — третья точка билдов

Деривация b11500 даёт тот же grammar id `9fa7e9f4359a9201`
(b11064 → b11337 → b11500): байт-контракт грамматики репо стабилен
по билдам; preflight зонда сверяет и предупреждает при сдвиге.

## C. Дефекты, найденные сэндбокс-валидацией (все закрыты в этой же итерации; закон «валидируй инструмент перед доставкой» отработал)

1. **Литералы руки B без JSON-кавычек** — правило canon-target
   собрано как `"the player"` вместо репо-формы `"\"loc_tavern\""`:
   модель ЗАКОННО выдавала `target: the player` без кавычек →
   JSON не парсился → off_grammar. Найдено smoke-проходом;
   исправлено (литерал = json.dumps(имя), побеги по закону
   brief/gbnf.py::_literal, контрольные символы отказывают громко).
2. **Слепой bind спавна** — health-check раньше poll'а маскировал
   умершего ребёнка, зонд мог говорить с чужим сервером на порту.
   Исправлено: отказ при уже обслуживаемом эндпоинте + poll
   раньше health.
3. **Стена памяти llama-server** — сервер растёт ~34 МБ на вызов
   с УНИКАЛЬНОЙ грамматикой (корпус даёт ~51/руку — снимок
   эволюционирует с миром): OOM-kill ~52-го вызова при 4.1 ГБ
   (дефолтные флаги при этом сами едят 3.5 ГБ — 4 слота × 4096).
   Исправлено инструментом: `--restart-per-stage always` (рестарт
   перед каждой стадией) + mid-arm рестарт-и-повтор с бюджетом;
   README документирует датум роста. На станции (32 ГБ) прогон
   проходит без рестартов; флаг остаётся страховкой.
4. **Seeded-рука детерминизма с разными сидами** — три разных
   сида мерили пустоту (различие гарантировано конструкцией).
   Исправлено: один-сид ×3 + cacheless-рука + раздельные
   вердикты холод/тепло/рестарт.
5. **Leak-счётчики смешивали семьи** — ghost-счётчик ел F6-цели.
   Исправлено: семейное разделение F3 (догадка/ghost-попытка/
   отказ/LEAK) × F6 (payload/legit/declined).
6. **Мёртвые циклы не видны в census** — engine_failure циклы
   молча съедали базу сравнения. Исправлено: колонки eng_err/
   off_gr в таблице + строка «сравнимых из N».
