песочнице не хватает RAM под 5+ ГБ модель без GPU — проверено)»

### A.2 station_hroom v2.0 (внешний пак, Правило 9; исходник —
docs/station/archive/canonsim_hroom_pack_v2.0.zip, 4 файла)

Ядро v1.0 ПОСЛОВНО (targeted-правки над копией v1.0, никогда
регенерация — AGENTS §2.5): импорт машинерии m6 из соседнего
пака, форк Battery.h_cycle с двумя дельтами v1.0 (потолок 832 +
prose_full/head_chars), классификатор LOOP/BLEED/BURN/LEGIT,
рецикл/возобновление/always-a-zip. Ровно ТРИ дельты v2.0:

1. **БЭНД-ОКНО (урок KI#122, перенесённый на hroom-линию).**
   v1.0 выводил бенд из пречека --list-devices (`cuda_visible`)
   — прибор того самого класса, который v6.2 списал: пречек НЕ
   видит сервер-сайд провала загрузки CUDA-DLL («cuda» при
   фактическом CPU) и не различает полосы по данным. v2.0
   выводит бенд из маркеров окна -lv 4 в СОБСТВЕННОМ логе
   сервера hroom (m6._band_from_log — тот же вывод, что v6.2:
   ggml_cuda_init / load_backend-loaded-CUDA / «- CUDA» в
   device_info), записывает cuda_visible РЯДОМ как отдельный
   пречек-датум, в конце прогона — громкий вердикт
   (DEVICE_GATE.finalize, форма m6) + переприцел бенда в отчёте;
   attach-форма (без серверного лога) честно читается «not
   derivable», никогда угадыванием. Пре-v6.2 м6-пак рядом
   (нет _band_from_log) — громкое предупреждение на старте.
   Функция `_band_line` — чистая, покрыта юнитами на четырёх
   формах лога.
2. **det_h-ДАТУМ (урок m5 det-h, перемерянный на полосе самого
   прогона).** Оговорка v1.0 №2 называла вопрос: повторный
   вызов temp-0 с грамматикой не байт-идентичен (датум m5,
   0.6B-CPU-полоса). v2.0 меряет его на КАЖДОЙ полосе, включая
   производственную: тот же гибридный вызов дважды на руку —
   h0 (temp 0, форма m6 run_det h-половины ПОСЛОВНО: «I look
   around the tavern», сид-125 бут, сид 42, полное сравнение
   байтов, дайджесты) + h8-близнец (temp 0.8 — собственный
   датум сидированной руки). Запись в det.jsonl (резюмируемая,
   закон m3), секция THE DET DATUM в отчёте. НИКОГДА не гейтит
   производный вид «416» — тот закон внутри-вызовный по
   построению (потолок только обрезает); датум отвечает только
   за воспроизводимость ПЕРЕЗАПУСКА пака.
3. **hroom_units.py (10 чистых законов — «всё, что может
   потребовать тестирования», вызов владельца; форма m6_units).**
   Классификатор: четыре вердикта на своих детекторах (петля
   k-1/k-3, чистый коллапс словаря без петли, BLEED по флагу,
   BURN по голове и по cpt с НЕ-коллапсным словарём, LEGIT на
   прозе-скорости зн/ток) + приоритет LOOP > BLEED > BURN
   (петля-с-bleed = LOOP; bleed-с-вырожденным-cpt = BLEED);
   подпись петли на краях; арифметика производного вида 416
   по синтетическому arm-jsonl (распределение, счёт сверх-416,
   классы упёршихся, стены); три ветки вердикта; чтение
   det-леджера; бэнд-строка на ЧЕТЫРЁХ формах лога (окно без
   маркеров = НЕ ВЫВОДИМ, никогда «cpu из тишины»; честный cpu
   c device_info; ЛОВУШКА «offloaded…to GPU» на чистом CPU —
   маркер НЕ является; cuda-форма — РЕАЛЬНЫЕ строки лога
   владельца) + attach; рендер --help (урок KI#121 перенесён и
   на парсер hroom — subprocess-запуск, rc=0).

## D. Риски

- **Полоса ≠ продакшн**: 0.6B-CPU-датум — ВАЛИДАЦИЯ прибора
  (зубы против известного результата), не производственный
  ответ; производственное распределение снимает станционный
  прогон тем же паком (Gemma-4-E4B). Отчёт несёт бенд/билд/
  модель в шапке.
- **Бэнд-вердикт — спавн-сторонний прибор**: attach-форма (--
  endpoint) честно читает «not derivable» — окно -lv 4 печатает
  только спавн; для станционного прогона это не ограничение
  (форма по умолчанию — спавн).
- **det-датум не гейт**: identical=False на h0 не подрывает
  производный вид 416 (внутри-вызовный закон); он отвечает за
  воспроизводимость перезапуска. На 0.6B-полосе h0 False / h8
  True; производственная полоса скажет своё.
- **Один хвостовой сдвиг (265 против 138)**: недетерминизм
  повторного вызова на вырожденно-лупной полосе; счёты/классы/
  аттракторы воспроизводимы; если станционный прогон Gemma
  даст другие индивидуальные длины при тех же счётах — это
  ожидаемое поведение полосы, не дефект прибора.
- **Батарея m6 не входит в этот пак**: R/G/RU/narrate — уже
  сняты и прочитаны (iter-374); повторная съёмка — трата
  станционного времени без нового вопроса (D-250: базис
  продвижения COMPLETE). Владелец волен прогнать m6-батарею
  v6.2 снова — пак лежит рядом, зависимости нет.
