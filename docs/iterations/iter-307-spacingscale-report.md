## B. Что исполнено

### B.1 Инвентаризация (измерение прежде правки)

Персистентный скрипт по тому же методу, что V2: **131 объявление**
padding/margin/gap вне `:root`, **149 употреблений литералов**,
**17 органических значений** — в точности заявка iter-304.
Распределение: 10px×30, 8px×26, 6px×21, 4px×12, 12px×11, 2px×10,
3px×8, 1px×7, 16px×7, 7px×5, 14px×4, 5px×3, одиночки 9/18/20/34/48.

### B.2 Токены `:root` (+10)

```css
--space-1: 2px;   /* optical: hairline gaps, chip insets */
--space-2: 4px;   /* optical: tight insets, code chips */
--space-3: 6px;   /* component inner: dense rows, label pairs */
--space-4: 8px;   /* component: controls, list gutters */
--space-5: 10px;  /* component: the workhorse inset */
--space-6: 12px;  /* component upper: group gaps */
--space-7: 16px;  /* section lower: surface padding, grid gaps */
--space-8: 20px;  /* section: workspace gutters */
--space-9: 32px;  /* section upper: major indents */
--space-10: 48px; /* major: scroll breathing room */
```

Полосы §1.1 (optical 2–4 · component 6–16 · section 20–32 · major
48) — шкала «tunable starting point», поэтому частотные тяжеловесы
остались точными, а не притянуты к чужим шагам.

### B.3 Замены (149 употреблений, счётчики заассерчены скриптом)

- **Точные (119/149)**: 10/8/6/4/12/2/16/20/48px ложатся на свои
  шаги без дрейфа.
- **Слияния-близнецы (30/149, макс дрейф 2px)**: 1→2, 3→4, 5→6,
  7→8, 9→8, 14→16, 18→16, 34→32. Каждый — заявленный выигрыш
  консистентности: двухколоночные сетки выровнены на 16
  (`.columns` 16, `.models-arrival` 14→16 при том же 860px-брейкпоинте;
  `.chat-overrides` 12 — on-grid, остаётся); отступы списков на 16
  (`control-reasons` 16 + `preset-diff` 18→16 — одна роль, один
  шаг); пилл-чипы идентичны 2/8 (`.tag` и `.freshness` 1×8/1×9 →
  2×8); микро-поля сохраняют дифференциал (3→4 и 5→6: пара
  «верх/низ» 2px не изменилась).
- **0 и auto — литералы по закону** (семантика нуля/авто — та же
  форма, что легальный 0 в составных радиусах V2).
- Составные формы переписаны var()-выражениями: `gap: 8px 16px` →
  `var(--space-4) var(--space-7)`; `padding: 7px 10px 8px 34px` →
  `var(--space-4) var(--space-5) var(--space-4) var(--space-9)`.
- Трансформация исполнена персистентным скриптом со счётчиками:
  per-value ожидание≠факт → отказ записи. Счётчики сошлись точно
  (149/149; распределение по шагам: 17/20/24/32/30/11/12/1/1/1).
  Один косметический след процесса: финальный print-цикл скрипта
  упал ПОСЛЕ успешной записи (сортировка по float от строк с
  суффиксом «px») — исправлено в артефакте скрипта; сама запись
  прошла все ассерты.

### B.4 Guard V3 — исполняемый закон (tests/architecture/guard.test.ts)

+40 аддитивных строк (git diff проверен: +40/−0). Property-скан:
`(?:row-|column-)?gap|padding|margin`(+стороны) `:` значение →
сырой px/rem ≠ 0 = RED с именованием файла, свойства и значения.
0/auto/em/% легальны (контекстные отношения, форма исключения

### B.5 Живой визуальный пруф (собственный проход ряда — закон iter-304)

  computed-стилы.
- **Машинная сверка** (скрипт, не глаз): **261 computed-значение** —

  дрейфом, 224 без изменений**; каждый дрейф — один из восьми
  заявленных слияний, недекларированный дрейф или off-grid значение

  живом ходе: `8 10 8 10` / `8 10` / margin-bottom `4` — слияния
  7→8 и 3→4 вживую, никогда по оторванному селектору.
- **Ноль ошибок консоли, ноль page errors** на обоих проходах.

  отдельны от spacing; свой ряд, если владелец назовёт.

  §2.1-измерения без потребителей; owner-gated, никогда
  спекулятивно.
- Клавиатурные/focus-ряды, accessibility-базлайн (LAW §15) — свои
  ряды (ux-1), не часть токен-ряда.
