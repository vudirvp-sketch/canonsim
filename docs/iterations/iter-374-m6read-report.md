## B. THE BAND VERDICT — вопрос серии закрыт (прибор + физика, оба живьём)

**Маркеры в ОБОИХ логах** (`-lv 4`, `verbosity = 4` записан в каждом):
`ggml_cuda_init: found 1 CUDA devices (Total VRAM: 12287 MiB)` →
`load_backend: loaded CUDA backend …ggml-cuda.dll` →
`device_info: CUDA0 : NVIDIA GeForce RTX 3080 Ti (12287 MiB,
11100 MiB free)`. **FULL offload в обоих:** Kev **33/33** слоёв,
Gemma **43/43**; веса по memory-breakdown 4265 MiB (файл Kev Q8
4176 MiB ✓) и 2868 MiB. `cuda_gate.json`: `bands` обе `'cuda'`,
`vram_plan` FULL offload обе, устройства записаны.

**Физика, переприведённая из этого прогона:** Gemma prompt eval
**med 4015 / max 4445 tok/s** (44 вызова; 21 разогревочная строка
33–647 tok/s — класс первых вызовов после спавна), decode **med 68 /
max 118 tok/s** — GPU-класс для 4.3B Q4_K_M (16-поточный CPU дал бы
prefill 100–400 и decode 5–20). Роутер: per-request тайминги на
`/v1/systemone` при `-lv 4` не печатаются — вместо них стеновая
физика: med 1531 входных токенов внутри med 0.546 с вызова = **≥2800
tok/s эффективных end-to-end**, что для CPU-prefill 4.2B Q8 на 8
потоках неисполнимо внутри стены.

**Последствие для серии:** латентности m4/m5/m6 ВСЕГДА были числами
CUDA-бенда — R med 0.52–0.556 с и G med ~0.49–0.50 / max ~2.9 с
согласованы по всем трём прогонам; чтение KI#119 «m5 = CPU-бенд»
отозвано вместе с ложоотрицанием прибора; оценка iter-358 «GPU ×6.3»
ВОССТАНОВЛЕНА направленно (точный множитель неизмерим — станционного
CPU-прогона на этих моделях не существует). Латентный гроссбух m6
носит честную метку бенда впервые в серии.
